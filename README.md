# TimeTaskBot

TimeTaskBot — это Telegram-бот для учета рабочего времени, разработанный на Java с использованием Spring Boot. Проект создан как демонстрация принципов объектно-ориентированного программирования (ООП) и качественной архитектуры серверного приложения.

## 🚀 Основные возможности
- **Управление задачами**: создание, редактирование, удаление и просмотр списка задач.
- **Таймер учета времени**: фиксация UTC-времени старта и остановки задачи с расчетом затраченного времени.
- **Статистика**: суммарное время по задачам и детальные интервалы работы по каждой задаче.
- **Ограничения**: в системе может быть активен только один таймер одновременно для одного пользователя.

## 🛠 Технологический стек
- **Java 21** & **Spring Boot 3**
- **Gradle** (Система сборки)
- **PostgreSQL** (База данных)
- **Spring Data JPA & Hibernate** (ORM)
- **TelegramBots API** (Взаимодействие с Telegram)
- **JDK HttpServer** (Webhook endpoint для Telegram)
- **Liquibase** (Миграции базы данных)
- **Lombok** (Генерация кода)
- **MapStruct** (Маппинг DTO)
- **Docker & Docker Compose** (Контейнеризация)

## 🏗 Архитектура и ООП
Проект построен по принципам **Clean Architecture** и демонстрирует следующие концепции ООП:

### 1. Инкапсуляция
- Все поля сущностей (`User`, `Task`, `TimerSession`) скрыты (private) и доступны через геттеры и сеттеры (генерируются Lombok).
- Логика работы с данными сосредоточена в сервисах, скрывая детали реализации от контроллеров (в данном случае — обработчика команд бота).

### 2. Наследование
- Использование базового класса `BaseCommand`, который содержит общую логику для всех команд бота.
- Иерархия классов в пакете `entity` и `command`.

### 3. Полиморфизм
- Интерфейс `Command` определяет контракт для всех действий пользователя. Бот обрабатывает входящие обновления через единый интерфейс, вызывая метод `execute()`, не зная конкретной реализации команды.

### 4. Интерфейсы и Абстракция
- Использование интерфейсов для репозиториев (`UserRepository`, `TaskRepository` и т.д.) позволяет абстрагироваться от конкретного способа хранения данных.
- Разделение ответственности между слоями (Controller -> Service -> Repository).

### 5. Паттерны проектирования
- **Command Pattern**: каждая операция бота инкапсулирована в отдельный объект команды.
- **Repository Pattern**: для работы с БД.
- **Service Layer**: бизнес-логика вынесена в отдельные сервисы.
- **DTO & Mappers**: разделение внутренних сущностей БД и объектов передачи данных.

## 📦 Структура пакетов
- `bot`: Настройка и запуск Telegram-бота.
- `command`: Реализация паттерна Команда для обработки действий пользователя.
- `service`: Бизнес-логика приложения.
- `repository`: Слой доступа к данным.
- `entity`: Доменные модели (сущности БД).
- `dto`: Объекты передачи данных.
- `mapper`: Преобразование между Entity и DTO.
- `config`: Конфигурационные классы Spring.
- `validation`: Валидация входных данных.

## 🤖 Команды и действия бота

Список команд должен поддерживаться актуальным при добавлении или удалении команд в пакете `command`.

### Текстовые команды

- `/start` — зарегистрировать пользователя и показать приветствие.
- `/help` — показать краткую справку.
- `/tasks` — показать список активных задач.
- `/create_task` — создать новую задачу; бот попросит название, затем описание.
- `/stats` — показать статистику по задачам с кнопками перехода в детали.

### Inline-действия

- `task_details:<taskId>` — открыть карточку задачи из списка задач.
- `start_timer:<taskId>` — запустить таймер учета времени по задаче.
- `confirm_start_timer:<taskId>` — подтвердить остановку текущего таймера и запуск нового.
- `stop_timer:<sessionId>` — остановить таймер учета времени и обновить карточку задачи.
- `skip_task_description:<taskId>` — создать задачу без описания.
- `edit_task:<taskId>` — выбрать поле задачи для редактирования.
- `edit_task_title:<taskId>` — запросить новое название задачи.
- `edit_task_description:<taskId>` — запросить новое описание задачи.
- `task_stats:<taskId>` — открыть статистику задачи с интервалами работы в UTC.
- `confirm_delete_task:<taskId>` — запросить подтверждение полного удаления задачи.
- `delete_task:<taskId>` — полностью удалить задачу вместе с историей времени.

## 🚦 Запуск проекта

### Требования
- Docker и Docker Compose

### Инструкция
1. Склонируйте репозиторий.
2. В корне проекта создайте папку `env` и файл `.env` в ней (используйте `env/.env.example` как шаблон):
   ```bash
   mkdir env
   cp env/.env.example env/.env
   ```
3. Заполните Telegram-настройки в файле `env/.env`:
   - `BOT_TOKEN` — токен бота.
   - `BOT_USERNAME` — username бота.
   - `BOT_WEBHOOK_URL` — публичный HTTPS URL webhook endpoint, например `https://your-domain.example/telegram/webhook`.
   - `BOT_WEBHOOK_PATH` — локальный путь endpoint, по умолчанию `/telegram/webhook`.
   - `BOT_WEBHOOK_PORT` — локальный порт webhook server, по умолчанию `8080`.
   - `BOT_WEBHOOK_SECRET` — секрет для проверки заголовка `X-Telegram-Bot-Api-Secret-Token`.
4. Для быстрого запуска (требуется установленный и **запущенный** Docker):
   ```bash
   ./gradlew bootRun
   ```
   *Spring Boot автоматически запустит базу данных в Docker контейнере. Если Docker не установлен, необходимо иметь локальный экземпляр PostgreSQL и вручную создать базу данных `taskchrono`.*

5. Если при запуске возникает ошибка `Connection refused` к `localhost:5432`:
   - Убедитесь, что Docker Desktop запущен.
   - Проверьте, не занят ли порт 5432 другим приложением.
   - Попробуйте запустить базу данных вручную: `docker-compose up -d db`.

6. Либо запустите все сервисы через Docker Compose:
   ```bash
   docker-compose up -d --build
   ```
7. Приложение поднимет HTTP endpoint на `BOT_WEBHOOK_PORT` и зарегистрирует webhook в Telegram через `BOT_WEBHOOK_URL`. Long polling не используется.

## 📊 Схема базы данных
Управление схемой осуществляется через **Liquibase**. При запуске приложения все необходимые таблицы создаются автоматически.
Основные сущности:
- `users`: Пользователи бота.
- `tasks`: Задачи, созданные пользователями.
- `timer_sessions`: Сессии учета времени.
